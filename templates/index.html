DFD Engineering Guide & Documentation

A complete reference on Data Flow Diagram symbols, hierarchy levels, and academic rules.

1. What is a Data Flow Diagram (DFD)?

A Data Flow Diagram (DFD) is a standardized graphical model representing the flow, transformation, and storage of data throughout an information system. Unlike procedural flowcharts, a DFD focuses purely on what data moves and transforms rather than control logic, sequencing, or loops.

2. Core DFD Components

Process:

Transforms incoming data into outgoing data. Must have an identifier (e.g. 1.0, 2.1) and an active verb phrase title.

External Entity (Source / Sink):

People, systems, or organizations outside the boundary of the system that produce inputs or consume outputs.

Data Store (Repository at Rest):

Persistent databases, cache layers, or physical archives where information is retained for later retrieval.

Data Flow (Packet in Motion):

Directional pipeline carrying structured payloads, messages, or documents between processes and nodes.

3. Standard DFD Academic Validation Rules

Rule 1: No Direct Entity-to-Entity Flows

External entities cannot directly send data to other external entities within the system model. All data must pass through an internal Process.

Rule 2: No Direct Store-to-Store Flows

Data cannot move autonomously between two data stores. A Process is required to extract, validate, and write the data.

Rule 3: No Direct Entity-to-Store Flows

An external actor cannot directly read or write to a data store without an intermediary Process handling validation.

Rule 4: No Black Holes or Miracles

Processes cannot have only inputs (Black Hole) or only outputs (Miracle). A valid process must transform inputs into distinct outputs.

4. DFD Decomposition Hierarchy

  • Level 0 (Context Diagram): High-level view showing the entire system as a single process (0.0) interacting with external entities. Data stores are hidden at this level.
  • Level 1: Decomposes the single system process into 3–7 primary sub-processes (1.0, 2.0, 3.0) and reveals the primary system data stores.
  • Level 2+: Further explodes a complex process (e.g. 2.0) into detailed child functional steps (2.1, 2.2, 2.3).
